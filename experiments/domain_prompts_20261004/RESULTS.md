# 도메인별 구체성 프롬프트 적용

## 요청과 변경

6개 도메인의 생성 프롬프트를 **작성 맥락 → 타입별 전개 순서 → 필요한 세부 사실 → 구체적인 서술 예시 → 일관성 확인**으로 구성했다. 고객지원 외 도메인도 같은 수준의 업무별 사실 요구를 갖도록 작성했다.

| 도메인 | 구체적으로 전개할 내용 |
| --- | --- |
| 고객지원 | 고객 요구·발생 조건 → 자료/진단별 확인 결과 → 조치 근거·현재 상태·다음 확인 |
| 경력·교육 | 과제·제약 → 본인 행동·도구 → 관찰/측정 근거 → 성과·지원 목적과의 연결. 학사 문서는 기간/과목별 내역과 계산 |
| 의료 | 증상 시작·빈도·악화/완화·생활 영향 → 응답/관찰/검사 구분 → 기존 자료·미확인 범위·인계. 청구는 비용과 증빙 대조 |
| 금융 | 자금 용도·거래별 일시/금액/경로/상태 → 증빙·산식·합계/잔액 → 실행 조건·신청/승인 구분 |
| 법률 | 당사자별 행위·반응의 시간순 경위 → 주장별 증거와 한계 → 피해 산정·이전 협의·구체적 이행안 |
| 계약 | 의무 주체·대상·수량·규격·기한 → 인도/검수 기준 → 지급 발생 조건·보완·변경/종료 정산 |

전체 실행 지침: [DOMAIN_PROMPTS.md](../../DOMAIN_PROMPTS.md). 원본 Git `deaa2f6403a22253c9ebc70fe9ead5563d5257bd`의 도메인별 생성 함수와 subtype 형식 분리를 참고했다. 원본의 개인정보 토큰·당사자 강제 규칙을 복제한 것은 아니며 이 파이프라인의 고정 그래프·귀속 규칙을 유지한다.

## 생성 단계의 구체성 지시

- 각 필수 사실을 일반적인 한 줄 요약으로 끝내지 않는다. 사례·경위는 조건/시점 → 행동/확인 방법 → 관찰 결과 → 판단 이유로 전개한다.
- 계획의 `content_facts` 문자열에 항목에 맞는 서로 다른 세부 사실 2~4개를 담도록 지시한다. 이는 생성 지침이며 문장 수를 세는 새 탈락 기준은 아니다.
- 내역은 대상별 기간·수량·금액·결과와 계산/비교 근거를 적는다. 단순 인적사항을 여러 문장으로 늘리라는 의미는 아니다.
- 초안은 계획의 세부 사실을 축약하지 않고 해당 구간 목표 분량에 맞게 전개한다. 수정·추가에도 같은 도메인 지침을 전달하되 수정 범위와 기존 사실을 보존한다.
- 예시는 구체성 수준을 보여 주며 문장·사건·수치를 그대로 복사하지 않도록 명시한다.
- 엔티티의 실제 식별값 생성 금지와 비식별 사건 사실의 구체값 작성을 구분해 기존 표현의 모호함을 줄였다.

## 문장 나열 허용

78개 타입의 내역표 구간을 표·목록·문장 나열로 표현할 수 있도록 정의를 변경했다. 표 헤더·행·구분선 또는 연결된 산문 형식이 없다는 이유만으로 미충족이나 낮은 품질로 평가하지 않도록 독립 검수에도 반영했다. 필요한 내역 수, 실제 금액·근거·역할·계산의 충족 여부는 계속 확인한다.

생성용 도메인 예시와 확정 사실 계획은 독립 검수에 넘기지 않는다. 문서의 실제 내용으로 판단하는 기존 독립성을 유지했다.

## 검증

`python -m unittest discover -s tests -q`: **162개 통과**.

새 테스트는 6개 도메인의 실제 계획/초안 요청, 기존 구조화 초안과 실험용 산문 경로, 국소 수정·분량 추가의 도메인 전달, 78개 타입의 내역 필드 보존과 문장 나열 허용, 검수 입력에서 생성 예시 제외를 확인한다.

분량은 원본 subtype별 범위와 기존 하한을 유지한다. 추가 분량은 기존 원문을 보존한다. LLM 호출 단계·모델·문서당 최대 7회와 공유 재시도 1회 제한은 변경하지 않았다.

## 실제 LLM 실행 결과

`python -u -m experiments.verify_document_specs --run-id domain_prompts_20261004_v1`로 이전 실험과 같은 6개 대표 subtype을 새 계획·새 초안부터 생성했다. 실행은 정상 종료됐고 실행 중으로 남은 호출은 없다.

| 도메인 / subtype | 이전 → 새 본문 문자 수 | 하한 충족 | 새 검수의 타입 항목 | 새 품질 | 최종 결과 |
| --- | ---: | --- | ---: | --- | --- |
| 고객지원 / refund_request | 919 → 1,224 | 미충족 (1,500) | 검수 전 탈락 | - | 분량 추가가 요청량보다 짧음 |
| 금융 / fraud_report | 1,274 → 1,675 | 충족 (1,558) | 6/7 | 상 | 관계 근거 응답 형식 오류 |
| 법률 / mediation_application | 1,990 → 2,833 | 충족 (1,848) | 8/8 | 중 | 관계 근거 응답 형식 오류 |
| 의료 / registration | 993 → 1,356 | 미충족 (1,533) | 검수 전 탈락 | - | 분량 추가가 요청량보다 짧음 |
| 계약 / service | 2,026 → 1,820 | 충족 (1,658) | 6/7 | 하 | 당사자 역할 모순과 관계 근거 응답 형식 오류 |
| 경력·교육 / recommendation | 1,549 → 1,649 | 충족 (1,500) | 7/7 | 중 | 관계 근거 응답 형식 오류 |

분량 충족은 이전 3/6에서 4/6으로 늘었다. 검수까지 도달한 세 문서에서 구체성 관련 타입 항목은 법률 2/8 → 8/8, 경력·교육 2/7 → 7/7로 증가했다. 금융은 이전에 분량 단계에서 탈락했으나 이번에는 6/7과 전체 품질 `상`을 받았다. 경력·교육의 suitability도 `중`에서 `상`으로 바뀌었고, 새 추천서는 관찰 관계·서로 다른 사례·행동과 결과를 모두 충족했다. 이 결과는 도메인 프롬프트에 필수 사실의 세부 전개를 넣는 방향이 실제 본문 구체성을 높였다는 소규모 근거다.

계약은 이전과 같은 6/7이고 전체 품질도 `하`였다. 서비스 제공자·대금 지급자의 방향이 본문에서 뒤바뀌는 문제가 남았다. 고객지원과 의료는 본문이 각각 305자, 363자 길어졌지만 추가 단계가 요구한 문자 수를 만들지 못해 검수까지 도달하지 못했다.

최종 채택은 이전과 동일하게 0/6이다. 4건은 본문 타입 항목과 별개인 독립 검수 응답의 `REVIEW_ENDPOINT_EVIDENCE` 형식 오류로 탈락했다. 따라서 이번 실행은 **본문 구체성 개선은 확인했지만 파이프라인 최종 채택률 개선은 확인하지 못한 결과**다. 이 검수 응답 오류와 짧은 추가 분량은 다음 수정 대상으로 분리한다.

총 호출은 34회(계획 6, 초안 7, 수정 7, 추가 9, 검수 5), 추정 비용은 USD 0.1119026이다. 이전 실행은 30회, USD 0.0979839였다. 두 실행은 같은 대표 subtype을 사용했지만 계획과 생성 표본을 새로 뽑은 소규모 전후 비교이므로 인과적인 A/B 결과로 해석하지 않는다.

원문과 단계별 요청·응답은 [`runs/domain_prompts_20261004_v1`](../../runs/domain_prompts_20261004_v1)에 보관했다. 실제 생성 요청에서 도메인 지침이 들어간 예시는 [`actual_prompts`](actual_prompts)에서 확인할 수 있다.

## 후속 출력 감사

금융 원문에는 typed placeholder가 아닌 `E2`, `E3` 등의 내부 엔티티 ID가 일반 문장에 남아 있었다. 슬롯 필링은 `<TYPE:E번호>`만 실제 값과 span으로 바꾸므로 이 실행의 금융 문서는 최종 산출물로 사용할 수 없다. 위 `상` 등급은 당시 검수 모델의 하위 품질 판정 기록일 뿐 유효한 최종 문서 판정이 아니다. 실행 산출물은 감사 재현을 위해 수정하지 않고 보존한다.

후속 코드에서는 일반 문장 속 bare E ID가 계획에 등록돼 있으면 계획의 타입으로 typed placeholder를 복원하고 변환 이력을 남긴다. 등록되지 않은 ID는 초안 진단, 슬롯 렌더링, 최종 출력 검증에서 차단한다. 기본 관계 검수는 근거 배열·인용 수집을 없애고 관계 성립·방향·당사자 귀속·PII/NON_PII/AMBIGUOUS·계획 밖 관계만 판정하는 `privacy_only_v1`로 바꿨다. 문서 형식·타입별 필수 내용·전체 품질은 별도로 계속 검사한다. 분량 추가 요청은 현재 길이·하한·부족분을 코드로 계산해 `부족분×1.5`를 목표로 전달한다.

검증 해석 보충: 위 표의 새 품질·타입 항목 수는 관계 증거 검증에서 실패한 검수 응답의 관찰값이며 유효한 최종 평가가 아니다. 그 수치만으로 본문 구체성 개선이 입증됐다고 해석하지 않는다. 실제 종료 사유·본문에서 남은 일반적 표현·역할 모순·반복·내부 ID 노출과 실행 무결성 확인은 [VALIDATION.md](VALIDATION.md)에 별도로 기록했다.
