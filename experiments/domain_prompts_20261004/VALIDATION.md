# 도메인 프롬프트 검증 — 실제 종료 상태 기준

6개 도메인의 프롬프트를 작성 맥락·타입별 전개 순서·세부 사실·서술 예시·일관성 확인으로 분리했다. [전체 지침](../../DOMAIN_PROMPTS.md)은 78개 subtype 정의와 함께 계획·초안·수정·분량 추가에 적용된다. 문장 나열·목록·표를 허용하고 실제 필수 내용의 충족 여부를 검수한다.

## 결과

고객지원·의료는 독립 검수까지 도달하지 못했다. 나머지 4건도 검수 응답 자체가 증거 검증에 실패했다. 따라서 그 응답의 높은 품질 평가나 `spec_checks=true`는 **유효한 최종 품질 통과가 아니다**. 타입별 항목 충족 평가 수가 늘었다는 관찰만으로 구체성 개선이 입증됐다고 결론 내리지 않는다.

이전 실험은 분량 충족 3/6건, 최종 채택 0/6건이었다. 같은 대표 타입·seed·slot으로 계획과 초안을 새로 생성한 소규모 전후 비교이며, 통계적인 개선이나 인과관계를 입증하는 A/B 실험은 아니다.

## 본문에서 확인한 점

- 금융은 두 건의 150만원을 총 300만원으로 연결했고, 법률은 30만원 제안·상대의 10만원 요구·응답일·지급 기한을 기재했다. 의료 계획에는 복통 시작 시점과 식사 후 악화 조건이 들어갔다.
- 금융의 거래 내역, 법률의 쟁점·조정안은 표 헤더 없이도 검수 응답에서 항목 충족으로 평가됐다. 해당 응답은 별도의 관계 증거 검증에서 실패했다.
- 의료의 '일상생활에 지장', 계약의 '3개 주요 기능'과 '사용자 인터페이스의 완전성'처럼 실제 행동·기능·판정 기준을 충분히 설명하지 않은 내용도 남았다. 필수 사실마다 세부 사실 2~4개를 담으라는 지시가 모든 출력에서 지켜지지는 않았다.
- 용역 계약서에서는 서비스 제공 방향과 발주자·수급인의 귀속이 혼동됐다. 금융은 작성자 관점 불일치, 추천서는 인물 역할이 불명확한 문장이 지적됐다.
- 금융 본문에는 같은 사실의 반복과 `E2`, `E3` 같은 내부 ID 노출이 남았다. 글자 수 증가만으로 내용의 구체성 개선을 단정할 수 없다.

요청한 도메인별 구조화 프롬프트와 문장 나열 허용은 적용·검증했지만, 프롬프트 보강만으로 최종 채택 문제까지 해결되지는 않았다. 표 형태 제한만 사용자 요청에 따라 제거했고, 기존 분량·관계·개인정보·내용 품질 기준은 유지했다.

## 실제 요청과 실행 무결성
