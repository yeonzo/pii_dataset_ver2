# financial — 6개 타입

신청 조건·거래 내역·금액 계산·증빙·처리 상태를 구분한다. 소유자·출금 주체·수취인·지급 대상은 서로 다를 수 있다. 서식 작성 요령으로 본문을 대체하지 않는다.

## loan_application — 대출 신청서

- 작성자: 대출 신청인
- 독자: 여신 심사 담당자
- 작성 관점: `applicant_form`
- 당사자 역할: 차주:상환 의무의 주체 / 보증인:조건에 포함된 보증 주체

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 신청 목적과 조건 | 항목명: 확정된 값 또는 상태 | 자금 목적별 필요액 / 신청금액·기간·금리 조건 |
| 2 | 상환능력 자료 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 소득·지출·기존 채무의 기간별 내역 / 증빙 자료와 확인 범위 |
| 3 | 상환계획 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 회차별 원금·이자·상환 재원 / 수입 부족 시 대응 계획 |
| 4 | 보증·확인 사항 | 항목명: 확정된 값 또는 상태 | 보증 유무와 해당 시 범위 / 신청 의사·제출 자료·심사 상태 |

**상황별 포함·제외:** 보증인이 선정된 경우에만 누구의 어떤 채무를 보증하는지 쓴다. 신청 조건을 승인 조건으로 확정하지 않는다.

**완성 기준:** 필요액·신청액·상환계획의 계산이 연결되고 차주·보증인의 책임과 심사 상태가 분명하다.

## card_application — 신용카드 발급 신청서

- 작성자: 카드 신청인
- 독자: 카드 발급 심사 담당자
- 작성 관점: `applicant_form`
- 당사자 역할: 신청인:이용·결제 책임의 주체

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 상품 신청 | 항목명: 확정된 값 또는 상태 | 카드 유형과 선택 이유 / 이용 목적·예상 소비 항목 |
| 2 | 한도 및 결제 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 희망 한도와 산정 근거 / 결제일·결제 수단·관리 계획 |
| 3 | 이용 서비스 | 항목명: 확정된 값 또는 상태 | 신청한 알림·결제 기능 / 수령 방식과 이용 준비 |
| 4 | 확인과 신청 의사 | 항목명: 확정된 값 또는 상태 | 확인한 이용 조건·비용 / 접수·심사 상태와 신청 의사 |

**상황별 포함·제외:** 신규 신청은 발급 완료 카드번호나 사용 이력을 만들지 않는다. 재발급이면 기존 문제와 변경 범위만 확정한다.

**완성 기준:** 상품 선택·한도 근거·결제 관리·신청 서비스가 구체적이며 신청과 승인·발급을 구별한다.

## account_opening — 예금계좌 개설 신청서

- 작성자: 계좌 개설 신청인
- 독자: 계좌 개설 담당자
- 작성 관점: `applicant_form`
- 당사자 역할: 신청인:계좌 소유·거래 목적의 주체

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 개설 신청 | 항목명: 확정된 값 또는 상태 | 계좌 종류와 선택 이유 / 주요 거래 목적 |
| 2 | 예상 거래 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 입출금 경로·빈도·예상액 / 초기 입금의 출처와 금액 |
| 3 | 이용 서비스 | 항목명: 확정된 값 또는 상태 | 통장·체크카드 발급 신청 여부 / 채널·알림·연계 서비스의 선택 범위 |
| 4 | 확인과 처리 | 항목명: 확정된 값 또는 상태 | 확인 자료와 거래 목적 대조 / 신청·확인·개설 중 현재 상태 |

**상황별 포함·제외:** 급여용과 사업용 거래 목적을 섞지 않는다. 체크카드를 신청하지 않으면 카드번호나 카드 발급 완료를 추가하지 않는다.

**완성 기준:** 거래 목적·초기 자금·예상 거래가 연결되고 선택한 서비스와 실제 처리 상태가 일치한다.

## insurance_subscription — 보험 가입 청약서

- 작성자: 보험 청약자
- 독자: 보험 인수 심사 담당자
- 작성 관점: `applicant_form`
- 당사자 역할: 계약자:보험료 납부 주체 / 피보험자:보장 대상 / 수익자:조건에 따른 지급 대상

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 청약 당사자와 목적 | 항목명: 확정된 값 또는 상태 | 계약자·피보험자·수익자 역할 / 선택한 상품과 가입 목적 |
| 2 | 보장 내역 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 담보별 보장 대상·금액·기간 / 제외·면책 조건 |
| 3 | 보험료와 고지 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 납입 주기·금액·기간 / 고지 질문별 응답과 확인 필요 항목 |
| 4 | 청약 확인 | 항목명: 확정된 값 또는 상태 | 설명받은 조건과 유보 사항 / 청약·심사·승낙 중 현재 상태 |

**상황별 포함·제외:** 수익자가 별도 선정되지 않으면 새 인물을 추가하지 않는다. 청약 접수를 보장 개시나 보험금 지급으로 쓰지 않는다.

**완성 기준:** 각 당사자의 역할·담보·보험료·고지 응답이 연결되고 제외 조건과 승인 상태가 명확하다.

## wire_transfer — 송금·이체 신청서

- 작성자: 송금 지시인과 접수 담당자
- 독자: 이체 처리 담당자
- 작성 관점: `official_record`
- 당사자 역할: 송금인:출금·지급 지시 주체 / 수취인:입금 대상

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 송금 지시 | 항목명: 확정된 값 또는 상태 | 송금 사유와 지급 근거 / 요청 시점·금액·실행 기한 |
| 2 | 출금과 수취 정보 | 항목명: 확정된 값 또는 상태 | 출금 수단과 수취 대상의 구분 / 수취 정보 대조 결과 |
| 3 | 금액 확인 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 송금액·수수료·총 출금액 / 잔액·한도·실행 조건 확인 |
| 4 | 실행과 통보 | 항목명: 확정된 값 또는 상태 | 실행 전 확인 질문과 응답 / 접수·실행·반환 중 상태와 확인 시각 |

**상황별 포함·제외:** 예약 이체는 실행 완료와 구분하고 반환이면 반환액·사유를 기록한다. 송금인과 수취인의 계좌를 바꾸지 않는다.

**완성 기준:** 출처·도착지·금액·수수료 계산·처리 상태를 추적할 수 있고 실제 확인 내용이 있다.

## fraud_report — 명의도용·보이스피싱 신고서

- 작성자: 피해 신고인
- 독자: 금융기관 사고 접수·조사 담당자
- 작성 관점: `first_person_reporter`
- 당사자 역할: 신고인:피해 주장과 자료 제출자 / 상대방:확인된 거래 또는 의심 행위의 대상

| 순서 | 실제 항목명 | 표현 형식 | 반드시 채울 사실 |
| ---: | --- | --- | --- |
| 1 | 신고 개요 | 항목명: 확정된 값 또는 상태 | 피해 인지 시점과 신고 목적 / 확인된 거래 대상과 피해 범위 |
| 2 | 피해 경위 | 지정 화자의 연결된 서술; 사건·행동·근거·결과 | 최초 접근부터 거래까지의 시간순 행동 / 피해를 의심하게 된 구체 계기 |
| 3 | 거래와 증빙 | 항목별 내역과 대응 관계가 명확한 표·목록·문장 나열; 표 헤더는 필수가 아님 | 거래별 일시·금액·경로·상태 / 증빙별 입증 사실과 확인 불가 사항 |
| 4 | 조치와 요청 | 항목명: 확정된 값 또는 상태 | 차단·문의·신고 등 이미 취한 조치와 결과 / 지급정지·조사 요청 범위와 남은 확인 |

**상황별 포함·제외:** 계좌 이체 피해와 카드 부정사용을 구분한다. 의심 상대의 범죄를 확정하지 않으며 피해와 무관한 대출·보증 관계를 추가하지 않는다.

**완성 기준:** 일시·수법·거래금액·증빙·후속 조치가 사건으로 연결되고 작성 안내문이나 범죄 단정이 아니다.
